# Criminal Memo v2.2 — 한국어 OCR 비교 결과

결론: **기본 엔진은 Tesseract.js로 유지합니다.** PaddleOCR는 별도 실험 선택지·영역 재인식·명시적 순차 비교로 구현했습니다. 이 표본에서는 한국어 후보와 일부 자동값이 개선됐지만 Windows Edge file://, 공식 인식 가중치와 변환본의 동등성, 변환 출처의 라이선스 독립 확인이 남아 있어 즉시 교체를 권고하지 않습니다. 검사·죄명 전용 정밀 엔진으로 추가 실증하는 방안을 우선 권고합니다.

## 실제 사용한 모델·실행 방식

- PaddleOCR PP-OCRv5 `korean_PP-OCRv5_mobile_rec` 한국어 ONNX 변환본(입력 N×3×48×W, 출력 N×T×11947), `PP-OCRv5_mobile_det`(DB, ONNX opset14). 공식 Paddle 모델을 Python에서 실행하거나 직접 ONNX로 변환한 실험이 아닙니다.
- ONNX Runtime Web **1.23.2**, MIT, WASM CPU 1 thread. Tesseract.js **5.1.1**, 기존 kor+eng best_int 모델을 보존했습니다.
- 검출 모델은 RapidOCR v3.4.0 레지스트리의 SHA-256과 일치합니다. 한국어 모델은 monkt 변환본으로 출처를 표시한 공개 GitHub 미러를 커밋으로 고정했습니다. 모델 파일·공식 사전의 해시, ONNX 구조 검사, 사전 11945개+blank+space 일치를 확인했습니다. 한국어 모델 해시는 RapidOCR 변환본과 다르며 공식 가중치와 동일하다고 주장하지 않습니다.
- 공식 PaddleOCR Apache-2.0 라이선스 원문 및 RapidOCR 라이선스를 포함했습니다. 인식 변환본의 Apache-2.0 표기는 미러의 고지에 근거하며 upstream 모델 카드와 변환 가중치의 독립 검증은 미완료입니다. [상세 출처와 SHA-256](../experimental/paddle/MODEL_PROVENANCE.md), [구조·파일 검사](../experimental/paddle/MODEL_MANIFEST.json).
- 모델은 **Uint8Array**로 `InferenceSession.create`에 전달합니다. WASM 및 로더는 HTML 내 바이트에서 만든 **Blob URL**입니다. 직접 wasmBinary 방식은 Blob Worker 안의 Emscripten 상대 URL 계산에서 실패했으며, 공식 wasmPaths 옵션으로 Blob URL을 전달하여 해결했습니다. 보안 옵션을 해제하지 않았습니다.
- 검출→수평 DB 연결 요소 상자→영역 추출→한국어 인식→CTC→행/단어 위치 복원→기존 파서 순서입니다. 수평 상자·확장 후처리는 실험용이며 Paddle 원본의 회전 다각형 후처리와 동등하지 않습니다. PSM7 영역은 검출을 생략하고 한 줄 인식합니다. Paddle의 3/6/11은 모두 검출 후 인식이며 Tesseract의 PSM 알고리즘을 복제하지 않습니다.

## 자료와 판정 기준

저장소 공소장1·2와 그 합성 변형 **10문서/12개 피고인별 죄명 목록**입니다. 300DPI, 90DPI, 2도 기울기+잡음, 위치 이동, 6pt 작은 글씨, 잘못된 선택 텍스트, 깨진 선택 텍스트, 두 페이지 혼합 PDF를 포함합니다. 원본 PDF는 변경하지 않았습니다. 서로 독립적인 실무 문서 10개가 아니며 실무 정확도를 보장하지 않습니다. 사용자가 새로 제공한 비식별 오류 재현 문서는 없었습니다. 개인정보를 외부 API로 전송하지 않았습니다.

자동 정답/오답은 이 자료의 정답표와 완전 일치 여부입니다. 죄명은 순서·피고인 관계를 포함한 **전체 목록**으로 비교하며 공백만 정규화합니다. 정답 후보 포함은 최종값이 보류됐으나 정답 후보가 있는 경우입니다. 기타 확인 필요는 후보가 있으나 정답 전체와 일치하지 않는 경우, 미인식은 사용할 값/후보를 얻지 못한 경우입니다. 변호인은 이름 또는 규칙상 빈 출력값을 비교하며, 피고인 전체가 누락됐을 때 빈 변호인을 정답으로 계산하지 않습니다. 모든 자동값도 최종 사용자 원문 대조가 필요합니다.

## 영역 인식과 전처리

공소장1 원본 및 기울기+잡음 합성본의 정답 주석 영역(검사/죄명 각1개)에서 원본·그레이스케일·대비·적응형 이진화·기울기/잡음 보정을 두 엔진에 적용한 **40회**를 비교했습니다. 이 주석은 시험용이며 앱에 고정 좌표로 적용하지 않습니다. 전체 페이지와 수동으로 올바르게 고른 영역의 차이는 실제 자동 영역 탐색 성능과 구별합니다.

| 엔진 | 영역 항목 | 완전 일치 후보 / 10회 |
|---|---|---:|
| tesseract | 검사 | 9/10 |
| tesseract | 피고인별 죄명 전체 목록 | 9/10 |
| paddle | 검사 | 8/10 |
| paddle | 피고인별 죄명 전체 목록 | 10/10 |

이 주석 영역 시험의 검사 이름은 Tesseract가 9/10, Paddle가 8/10으로 오히려 낮았습니다. 따라서 검사 영역까지 일률적으로 Paddle로 교체할 근거는 없습니다. 전처리가 항상 개선되지 않습니다. 세부 원문·후보·신뢰도·시간은 [단일 OCR 원자료](paddle-benchmark.json)의 preprocessing 항목에 보존했습니다. 평균 신뢰도만으로 후보를 확정하지 않습니다.

## 실패와 한계

- 2도 회전+잡음은 Paddle 전체 OCR도 검사/피고인 구간을 잃었습니다. 정답 영역을 사람이 선택한 시험과 자동 탐지의 결과가 다릅니다.
- 작은 글씨 전체 OCR에서는 Paddle 파서 제안에 적용법조·구속·변호인 내용이 죄명 뒤로 섞였습니다. 앱 경로에서는 원문/정밀 후보와의 충돌·줄바꿈 검토로 보류됐습니다. 단일 전체 OCR의 오답을 제외하지 않았습니다.
- Paddle 앱 경로도 검사 1건 미인식, 검사 2건 정답 후보를 포함한 보류, 죄명 3건 정답 후보를 포함한 보류가 남습니다. 구속 등 다른 항목도 일부 보류됩니다. 실무 공소장 전체에 대한 성공 주장을 하지 않습니다.
- 표의 처리 시간은 단일 실행의 초기화 포함 합계로 통계적 우위나 최악시간 보장이 아닙니다. 문서당 OCR 시작 예산120초, 페이지당6회/문서32회, 작업30초(모델 초기화 별도60초), 영역300개/인식폭2048 제한을 두고 Worker 종료로 작업을 중단합니다.
- 메모리는 CDP에서 나열한 해당 브라우저 프로세스의 RSS를100ms 간격으로 합산한 관측 최대입니다. 공유 메모리는 중복 계산되고 순간 피크나 실제 private 메모리 최대는 측정하지 못했습니다. JS/WASM만의 피크도 아닙니다. 특히 Paddle 후보에서 약2.2GiB 관측값은 실제 저사양 Windows에서 추가 검증해야 합니다.
- 최초 시험 도구에서 25MB 스캔 PDF를 Array.from으로 넘기다가 Node heap OOM이 발생했습니다. base64/File API 전송으로 고친 뒤 20건 전체 시험을 다시 완료했습니다. 실패 실행의 수치를 비교 결과에 섞지 않았습니다. 앱의 File API 처리 오류라고 판단하지 않습니다.

## 업무 규칙 변경 및 보존

- 기재 나이는 모델/파서/화면/나이 판정에서 제거했습니다. 기존 statedAge/confirmedYear가 남은 객체도 세기 판정에 사용하지 않습니다. 앞6자리만으로 세기를 정하지 않고 확인한 전체 생년월일을 입력·수정합니다. 수동 날짜는 실제 달력 검증을 거치며 앞6자리의 OCR 오류까지 사용자가 수정할 수 있습니다. 미확정 DOB는 원을 그리지 않고 기소일 기준 <19/>70만 표시합니다.
- 이름만 변호인 출력, 없음/미기재 빈칸, 복수 피고인·죄명 번호, 빨강 O/검정 X 연속 한 줄, 사용자 검토·수정·다운로드를 유지합니다. **원본 양식 첫 페이지만 사용해 항상1페이지 출력**합니다. 원본파일을 바꾸지 않습니다.

## 실제 Windows Edge에서 남은 확인

Windows10/11의 실제 회사 정책·설치된 Edge에서 인터넷을 끈 뒤 ZIP을 풀고 HTML 더블클릭 실행, Blob Worker/동적 Blob 모듈/WASM SIMD 허용, 캐시 없는 최초 모델 로딩, 각 엔진과 수동 영역 OCR, 저사양 PC의 메모리·반응성, 두 페이지 피고인 관계, 사용자 후보 선택, DOB 수정, 1페이지 PDF 저장·다시 열기·인쇄를 확인해야 합니다. 관리자 권한·별도설치·보안정책 해제 없이 모두 통과하기 전에는 Paddle를 기본 엔진으로 채택하지 않습니다.

기록된 HTML 해시는 각 원자료의 htmlSHA256/htmlHashes를 참조하세요. 단일 전체 OCR 비교는 엔진 코드가 같은 앞선 후보 HTML, 앱 경로·통합/출력 검증은 최종 후보 HTML을 대상으로 했습니다. 단일 비교 이후 변경은 엔진 표기·오류 수명 관리·DOB 화면/규칙 및 안내이며 모델·전처리·CTC 인식 계산은 동일합니다.
