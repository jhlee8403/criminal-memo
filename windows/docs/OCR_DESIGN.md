# OCR v2.1 설계·검증 범위

## 확인한 기존 원인

1. 글자 수가 20개 이상이면 내장 텍스트를 그대로 사용하여, 선택 가능하지만 잘못된 숨은 텍스트 레이어를 검증하지 않았습니다.
2. 검사 파서가 같은 줄과 공백 구분만 처리했습니다. `검사:이승엽`, 라벨 다음 줄 이름, 같은 행의 여러 항목을 놓칠 수 있었습니다.
3. 죄명 파서가 번호 없는 다음 줄을 이어 읽지 않았고 인접한 적용법조와의 경계도 취약했습니다.
4. 전체 OCR을 한 설정으로 수행하고 실제 단어 좌표를 버렸습니다. 평균 신뢰도가 높아도 검사/죄명 자체가 누락·오인식될 수 있었습니다.
5. 정밀 영역을 단순히 크게 잡으면 밑줄과 다음 법조가 섞이고, 글자를 과도하게 확대하면 인식이 나빠질 수 있었습니다. 초기 정밀 실험에서 실제 관측했습니다.

## 4단계 진단과 출처

`diagnostics.pages`에 원본 내장 텍스트·위치, 전체 OCR 원문/줄/단어 위치·신뢰도·설정, 정밀 OCR 원문/영역·설정·시간, 품질·경로 결정을 유지합니다. 전체 OCR을 생략한 경우 빈 이력과 생략 사유가 남습니다. `draft.evidence`/`diagnostics.fields`에는 피고인별 항목의 후보 출처, 페이지·box, 선택값, 수동값, 충돌, 확인 필요 여부가 있습니다.

검사·기소일, 피고인별 이름·죄명·변호인·구속을 독립 관리합니다. 출처가 달라도 다른 피고인으로 판단되는 자료의 죄명을 자동으로 연결하지 않습니다. 원문과 순서/동일인 여부가 불분명하면 확인해야 하며 모든 문서의 동일인 정합을 보장하지 않습니다.

원문에 이름이 있는데 후보가 없으면 파서/영역 문제를, 전체 OCR에서도 없으면 인식 문제를, 내장 텍스트가 충분한데 잘못 선택되면 경로 문제를 진단할 수 있습니다. UI의 진단 단계 및 각 후보의 '원문 위치'에서 원문을 대조합니다.

## 하이브리드 경로

- 깨진 문자/사설 문자, 한글 자모 분리, 항목명 부재, 검사·죄명 누락/줄바꿈 모호함을 검사합니다. 20자 규칙 하나로 OCR을 결정하지 않습니다.
- 정상 내장 텍스트는 작업 텍스트로 유지합니다. 기본으로 검사·죄명은 영역 OCR과 대조하며, 사용자가 이 검증을 끌 수 있습니다.
- 의심되는 페이지는 전체 OCR을 추가합니다. 기본 PSM 3과 필요시 PSM 6 전처리 결과를 남깁니다.
- 항목명·단어 위치·피고인 구간·적용법조 등 인접 항목으로 영역을 찾습니다. 같은 행의 복수 항목도 위치별로 나눕니다. 죄명은 페이지가 바뀌어도 현재 피고인 구간을 유지합니다.
- OCR의 `죄멍`, `검시` 같은 근접 라벨은 **탐색 힌트**로만 쓰고 라벨/죄명을 임의로 고쳐서 확정하지 않습니다. 상단 상대 영역은 검사 검색 보조 범위일 뿐 정답 좌표가 아닙니다.
- 선택 가능 레이어의 좌표·폭 자체가 잘못될 수 있으므로 정밀 영역에서 필수값이 없으면 전체 OCR을 추가하고 그 위치로 한 번 더 탐색할 수 있습니다.

충돌하면 자동값을 비우고 검토를 요구합니다. 믿을 만한 내장 텍스트의 비충돌 값, 또는 전체 OCR와 서로 다른 전처리의 영역 OCR가 일치한 검사/죄명은 제안값으로 채웁니다. 같은 엔진의 일치가 정답 보장이 아니므로 PDF 생성 전 원문 대조 확인은 항상 필요합니다. 신뢰도 점수만으로 선택하지 않습니다. 애매한 죄명 줄바꿈은 일치만으로 확정하지 않습니다.

## 이미지와 전처리

전체 렌더 목표는 300DPI, 영역은 400DPI입니다. 실제 화소 예산/가로세로 길이에 맞춰 축소하며 유효 렌더 DPI를 기록합니다. PDF image 연산과 transform에서 원 이미지 DPI를 추정할 수 있으면 별도 기록합니다. 원래 저해상도인 문서가 고해상도로 복원된다는 뜻은 아닙니다.

단어 위치에서 값 부분을 좁혀 잡고, 짧은 글자는 목표 글자 높이를 고려해 분류용 크기를 정규화합니다. 렌더 DPI와 실제 분류 입력 DPI를 구분합니다.

전처리는 브라우저 Canvas/TypedArray만 사용합니다. 원본, 그레이, 대비, 적응형 평균 이진화, ±3도 행 투영 기반 기울기 추정 및 고립 노이즈 완화를 비교합니다. 기울기 근거가 약하면 0도로 유지합니다. 초기 행 간격 샘플링의 0도 편향을 수정했고 합성 -2/0/+2도 텍스트에서 반대 보정각을 확인했습니다. 짧거나 복잡한 영역에서는 각도가 검출되지 않을 수 있습니다.

검사와 죄명의 PSM(7/6/11)·언어(kor/kor+eng)는 독립 설정입니다. 수동 영역은 PSM과 전처리를 따로 선택합니다. 원문/여러 결과를 비교하며 특정 전처리가 늘 좋다는 가정은 없습니다.

## 한도와 메모리

자동 OCR은 페이지당 6회·문서당 32회, 새 호출 시작 시간 예산 120초, 개별 OCR 대기 제한 30초입니다. 최대 자동 영역은 페이지당 4개입니다. 입력 한도 50MB/100페이지도 유지합니다. 시간 예산은 브라우저/PDF 파싱/Worker 초기화까지 포함한 엄격한 최악 시간 보장이 아닙니다.

전체 작업 이미지는 900만 화소/최대 변 4300px, 영역은 300만 화소로 제한합니다. 순차 처리 후 작업 canvas를 해제하고, 미리보기도 한 페이지만 렌더링합니다. 다만 전체 브라우저·PDF 디코더·WASM 최대 RSS를 보장하지 않습니다. JS heap, renderer RSS 완료 후 스냅샷, 이미지 버퍼 추정치를 구분합니다.

한도에 걸린 검증은 확인 필요 상태로 남습니다. OCR 미처리 페이지가 있으면 추가 원문 확인·수동 보완 확인 전 생성을 막습니다. 무한 자동 재시도는 하지 않습니다. 수동 재인식도 한 번의 지정된 작업만 수행합니다.

## 기존 기능과 실행 제약

나이 계산 함수 본문은 f8e4c27과 동일합니다. 원본 PDF·템플릿·입력 좌표를 변경하지 않았습니다. 변호인 빈칸/이름, 색상별 OX 한 줄, 빨간 나이 타원, 미리보기·저장을 회귀 검사합니다.

라이브러리/모델/WASM/글꼴/템플릿은 계속 단일 HTML에 내장하고 외부 API를 호출하지 않습니다. 이 환경의 file://는 관리자 정책으로 차단됩니다. 메모리 브라우저 진단의 성공을 Windows Edge HTML 더블클릭 성공으로 보고하지 않습니다.

## 개발 테스트 재현

```sh
cd windows
npm ci --cache /tmp/criminal-memo-npm
npm run build
npm test
python scripts/prepare_fixtures.py
npm run test:browser
python scripts/verify_outputs.py
npm run test:ocr
npm run test:ocr-ui
node tests/image-components.mjs
python scripts/report_ocr.py
```

실험 자료는 원본 2개에서 만든 정상/300DPI 스캔/90DPI 스캔/작은 글씨/이동 배치/기울기·노이즈/불량 선택 가능 레이어/깨진 레이어/혼합 2페이지입니다. 독립 실제 사건 자료가 아닙니다. 새 실제 실패 PDF의 추가 평가가 필요합니다.
