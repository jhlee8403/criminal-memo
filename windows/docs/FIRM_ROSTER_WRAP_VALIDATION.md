# 법무법인 명단의 이름 내부 줄바꿈 수정

기준: `experiment/v1-auto-latest-pdf` / `183b249`. 2026-11-16.

## 확인한 원인

사용자가 추가로 제공한 추출 텍스트에서는 한 이름이 **한 글자 + 줄바꿈 + 두 글자**로
갈라져 있었다. 실제 인명·법무법인명은 새 테스트에 저장하지 않고, 같은 구조를
`강\n가상` 등의 가상 인명으로 재현했다.

실행 경로:

1. `변 호 인`은 기존 `heading()`에서 `변호인` 항목으로 정상 인식된다.
2. `fields()`의 `parts`와 `values("변호인", lines)`에는 마지막 담당변호사까지 존재한다.
   12명이 2~4줄에 걸쳐 있고 줄 끝 쉼표가 있거나 없어도 수집은 완료된다.
3. 기존 `CounselParser`는 쉼표와 줄바꿈으로 **먼저** 분리한다.
   따라서 `강\n가상`이 `강`, `가상`이라는 두 토큰이 된다.
4. 기존 이름 검증 `/^[가-힣]{2,10}$/`에서 한 글자인 `강`이 탈락해 `incomplete = true`가 된다.
   이어 `status = "needsReview"`, `name = ""`가 반환된다. 이 경로는 OCR=false에서도 재현된다.
5. 화면은 `needsReview`를 `(판정 불가)`로 표시한다.

**명단 인원수가 원인은 아니었다.** 기준 코드에서도 온전한 이름 12명이 여러 줄에
나열되면 성공했다. 주어진 괄호 포함 법무법인 정규식도 정상 동작하므로 다시 추가하지 않았다.

OCR=true이면 마지막 반환에서 상태가 `needsReview`로 바뀌는 별도 경로도 확인했다.
이때는 이름과 전체 `lawyers`가 성공적으로 반환되어도 상태만 보류된다. 이 정책과
OCR 엔진은 변경하지 않았다. 실제 문제 PDF 전체에서 이 플래그가 참인지는 미확인이다.

## 최소 수정

법무법인 이름 목록 분리 단계만 변경했다. 쉼표로 구분한 영역 안에서
한글 이름이 **1+2 또는 2+1글자**로 줄에 나뉜 경우에만 3글자로 복원한 뒤,
나머지 줄바꿈을 이름 구분자로 사용한다.

- 온전한 이름끼리의 줄바꿈은 그대로 구분자로 유지한다.
- 2+2글자를 임의로 하나의 이름으로 합치지 않는다.
- 다른 크기의 불완전한 조각은 추측하지 않고 기존 검토 필요 상태로 남긴다.
- 명백한 `추가 서류 제출`·`확인 필요` 같은 문구를 변호사 이름 목록으로 받아들이던
  검증 허점도 같은 법무법인 분리 단계에서 보류하도록 했다.
- 알려진 다음 항목·공소사실·첨부 경계와 반복 머리말 필터는 기존 구현 그대로 사용한다.
  인식하지 못한 다른 문장이 값에 남으면 안전한 복원을 보장하지 않는다.

국선·일반 변호인 처리, 다른 항목 파서, OCR, PDF 렌더러/좌표/원본 양식,
수동 입력 없는 구조는 변경하지 않았다. 변경 전후의 `core.js` 차이는 법무법인
명단 처리 부분에만 있다.

## 한계

사용자가 보내준 추출 텍스트의 이름 내부 줄바꿈은 가상 인명으로 실패를 재현해 수정했다.
**실제 문제 공소장 PDF는 개발 환경에 없으므로 그 PDF에서 성공했다고 단정하지 않는다.**
OCR 플래그, 다른 줄/페이지의 오독·머리말 등 원문 전체의 추가 요인은 미검증이다.
모든 실제 인명이나 문장 형태를 일반적으로 식별·복원하는 기능은 아니다.

관리 정책 `ERR_BLOCKED_BY_ADMINISTRATOR`로 `file://` 탐색이 차단되어 동일 배포 HTML을
메모리에 올려 검증했다. Windows Edge에서 더블클릭 실행은 미검증이다.
