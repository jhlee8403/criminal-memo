# 반의사불벌·친고죄 자동 표시 검증

기준 커밋 `5e341b7`, 새 브랜치 `experiment/v1-complaint-marks`. 기존 브랜치와 2페이지 원본 양식은 보존합니다.

## 추가 기능과 죄명 비교

`core.js`에 `complaintMarks(draft)`를 추가했습니다. 기존 국참의 `normalizedCharge()`를 사용해 NFC·공백·전각 괄호를 정규화한 뒤 Set의 전체 일치만 검사합니다. 모든 피고인의 추출된 죄명 목록을 검사하며, 두 항목은 독립적인 boolean 결과입니다. 파서나 기존 국참/소년/필요적국선 판단은 수정하지 않았습니다.

| 표시 | 정확히 일치시키는 죄명 |
|---|---|
| 반의사불벌 | 폭행, 존속폭행, 과실치상, 협박, 존속협박, 명예훼손, 출판물에의한명예훼손, 근로기준법위반, 근로자퇴직급여보장법위반 |
| 친고죄 | 사자명예훼손, 모욕, 비밀침해, 업무상비밀누설 |

13개 죄명 모두 지정한 항목에만 표시됩니다. `사자명예훼손`은 친고죄만 표시하며 반의사불벌에 표시하지 않습니다. `특수폭행`, `특수협박`, `업무상과실치상`, `폭행치상`, `존속폭행치상`, `모욕미수`, `명예훼손(가상)` 등은 부분문자열이 겹쳐도 표시하지 않습니다. `출판물에 의한 명예훼손`과 `모 욕`은 공백 정규화 후 일치합니다.

미추출·미상·판정불가 값이나 빈 죄명 목록에서는 표시하지 않습니다. 기존 국참의 양성 판정과 같이, 목록에서 정확한 대상 죄명이 확인되면 다른 피고인/항목의 미추출 때문에 확인된 일치를 숨기지는 않습니다. 미해당을 검정 X로 출력하지 않습니다. 사용자 지정 목록에 따른 표시이며 실제 사건의 예외나 법적 요건을 새로 판단하는 기능은 아닙니다.

## PDF 실측 좌표

현재 원본 `형사메모(1).pdf`(SHA-256 `b16fcb041110090725863c5a4934a03b80ea935f6086d9bcf7111528aeb6f75c`)를 렌더링하고 텍스트 좌표와 벡터 표 선을 확인했습니다. 단위는 pt, 아래 표는 페이지 왼쪽 위 기준입니다. PDF-lib 출력 시 기존 방식대로 y축을 변환합니다.

| 항목 | 인쇄 텍스트 bbox (x0,y0,x1,y1) | 타원 bbox (x0,y0,x1,y1) |
|---|---|---|
| 반의사불벌 | 517.759,155.362,562.745,164.828 | 517.1,149.0,564.5,170.4 |
| 친고죄 | 517.759,131.450,547.743,141.402 | 517.2,126.2,548.7,146.8 |

오른쪽 열의 세로 경계는 x=516.442..565.496입니다. 친고죄 행은 y=124.784..148.278, 반의사불벌 행은 y=148.278..171.772입니다. 타원은 빨강 RGB(1,0,0), 선 두께 1pt, 내부 채우기 없음입니다. 선 두께까지 고려해 각각의 행 내부에 머물며, 표 선이나 다른 항목을 건드리지 않습니다.

8배 렌더링에서 원본 글자의 검정 픽셀이 타원 선의 안쪽에 모두 포함되는지 검사했습니다. 실제 두 타원과 전체 페이지 이미지를 시각적으로 확인했습니다. 기존 필요적국선 타원의 좌표·선 두께 1.3pt는 그대로 유지합니다.

| 저장·변호인 독립 PDF 검사 | 29개 PDF, 275개 검사 통과 |

새 표시 시험의 전후 비교 5쌍에서는 두 타원이 추가되는 영역 밖의 첫 페이지 픽셀이 전부 같고, 텍스트·폰트·좌표도 같습니다. 미해당·미추출 시에는 첫 페이지 전체가 같습니다. 기존 구속 O/X, 소년 O/X, 국참 O/X와 필요적국선 타원도 보존됩니다.

검사한 모든 최종 PDF는 2페이지이며 두 번째 페이지는 원본의 크기·회전·내용 스트림·텍스트/폰트/좌표·렌더링 픽셀과 동일합니다. 날짜나 O/X를 두 번째 페이지에 추가하지 않습니다. 원본·UI·저장/OCR 구현·빌드 타깃·외부 라이브러리는 변경하지 않았습니다.

브라우저는 Chromium 103.0.5058.0, 실제 `file://`, 오프라인 컨텍스트로 실행했습니다. 외부 네트워크 요청과 페이지 실행 오류는 없었습니다. Edge 104 legacy PDF.js·사전 폴리필·단일 HTML 내장 구조를 유지했습니다. 회사 Windows Edge 104에서 이번 변경을 직접 실행하지는 못했으며, 회사 폴더 정책을 검증한 결과로 해석하면 안 됩니다. 회귀의 폴더 핸들은 기존 모의 객체입니다.

검증한 HTML SHA-256: `5004e2d67a1e0441e76d19f11691c3e7fb61f0d8a9e1976f7c50921f93d8fb3a`.
