# 법무법인 소속 변호인 출력 변경

기준: `experiment/v1-auto-latest-pdf`, `38ce690`. 2026-11-15.

출력은 `법무법인명) 담당변호사1 담당변호사2 …`이다. `법무법인`과 직함, 쉼표는
제외하며 이름 순서 및 모든 이름을 보존한다. 괄호 유무·법무법인/담당변호사의 줄
분리·담당변호사 목록 내 줄바꿈을 지원한다. 이름 중복도 원문 그대로 보존한다.
국선 `이름(국선)`, 변호인 없음/미기재의 빈칸 출력은 유지한다.

`CounselParser`만 수정했고 그 외 `core.js`의 파서/규칙은 기준 커밋과 바이트 동일하다.
PDF 렌더러는 기존 변호인 칸 좌표·크기를 유지하면서 해당 칸에 한해 11~4pt 범위에서
0.5pt씩 축소해 전체 내용을 배치한다. 다른 칸의 글자 크기 규칙은 변경하지 않았다.
4pt까지도 들어가지 않으면 기존 초과 오류를 반환하며 이름을 생략하거나 잘라내지 않는다.
OCR·UI·원본 PDF·검사/날짜/피고인/죄명/구속 파서는 변경하지 않았다.

## 검증

- `npm test`: 70개 통과. 괄호 유무, 줄 분리, 직함 제거, 순서/중복/전체 이름,
  국선·없음·미기재를 검사한다. 새 예시의 변호사 이름은 모두 가상 인명이다.
- `npm run build`, `npm run test:browser`: 통과. 기존 PDF 자동 생성과 OCR 회귀에
  더해 실제 메모 PDF 렌더러로 변호인 출력 예시 7개를 생성했다.
- `python scripts/verify_outputs.py`: 68개 통과. PyMuPDF로 7개 PDF의 변호인 칸에서
  모든 이름·순서·접두 형식, 직함/쉼표 제거, 글자 좌표가 기존 칸 안에 들어가는지 확인했다.
  12명 예시에서는 글자 크기가 8pt 미만으로 줄어들면서 전체 이름이 출력된다.
- 각 변호인 예시의 메모를 같은 입력의 기준 메모와 픽셀 비교해 변호인 칸 외 변경 0 확인.
- 실제 PDF 결과는 `artifacts/counsel-*.pdf` (로컬 테스트 산출물),
  보고서는 `counsel-browser-report.json`, `counsel-pdf-report.json`.

테스트는 가상 재현 자료와 기존 샘플을 사용했다. 실제 최신 공소장 전체 정확도를
보장하지 않는다. Linux 관리 정책으로 `file://` 탐색이 차단되어 동일 HTML을 메모리에
올려 검증했으며, Windows Edge 더블클릭 실행은 미검증이다.
