# v2.0 기본 기능 검증 기록

v2.1 OCR 개선의 최신 결과는 [OCR_V21.md](OCR_V21.md)를 참고하세요. 기존 PDF 출력 31개 검사는 v2.1에서도 다시 통과했습니다. 아래는 전환 초기의 기본 기능 검증 기록이며 현재 비교 수치를 대체하지 않습니다.

## 상태

**배포 후보이며 Windows Edge file:// 운영 검증은 미완료입니다.**

- 분기 기준: main `69ca759`. 기존 Swift 규칙 참조: `feature/ipad-memo-v1`의 `f808f29`.
- Node 24.22.1, Linux Chromium 156.0.8078.79, Python 3.12.14, PyMuPDF 1.26.6, numpy 2.3.5에서 실행.
- 테스트 의존성은 `scripts/requirements-test.txt`로 설치할 수 있습니다. 배포 프로그램은 Python/Node/서버를 사용하지 않습니다.
- 새 브랜치에는 `windows/`만 추가합니다. 저장소 원본 PDF 세 개와 기존 Swift 브랜치를 수정하지 않습니다.

| 피고인 | 이민주 | 김유나 / 이영수 |

| 검사 | 이승엽 | 이정현 |

원문 주민번호 뒷자리는 모델에 저장하거나 계산에 사용하지 않습니다. OCR 결과는 숫자·문장부호가 틀릴 수 있으므로 원문 확인이 필수입니다. OCR에서 이름·죄명이 읽혔다고 모든 필드의 정확도를 보장하지 않습니다.

## PDF 좌표·양식 검증

입력 좌표는 기존 Swift의 실제 1페이지 양식 분석을 계승했습니다 (좌상단 기준 pt).

| 항목 | x | y | 너비 | 높이 |
|---|---:|---:|---:|---:|
| 피고인 |33|128|140|111|
| 죄명 |180|78|151|161|
| 검사 |385|48|112|22|
| 변호인 |385|78|112|20|
| 기소일 |231|247|174|20|
| 구속 |537|48|25|22|
| 소년 타원 |174|730|26|15|
| 필요적국선 타원 |109|746|56|15|

- 원본을 pdf-lib로 열어 첫 페이지만 오버레이. 표·글자를 다시 그리지 않습니다.
- 실제 다운로드 PDF에서 한글 이름과 번호, 변호인 빈칸/이름, O/OX의 색상·한 줄·칸 경계를 확인했습니다.
- 원본과 2배 래스터 비교에서 입력 영역 밖(2pt 여유)의 변경 픽셀 0개.
- 실제 샘플 두 개에는 나이 원이 없어야 함을 확인했습니다.
- 확정한 가상 생년월일로 소년/필요적국선의 빨간 투명 타원이 추가되는지 확인했습니다.
- 긴 텍스트는 칸을 넘기 전에 오류를 발생시켰습니다. 구속 상태가 미확정이면 생성이 거부됩니다.
- NanumGothic 전체 글꼴 포함. 부분 포함에서 발견한 글자 누락 문제를 수정했습니다.

[실제 브라우저 다운로드 PDF의 이미지](generated-memo.png) — Python 좌표 시뮬레이션이 아닌 실제 웹 렌더러 출력입니다. 단, Windows Edge file 출력은 아닙니다.

## 미완료·제한

Windows Edge에서 더블클릭·실제 오프라인 회사 PC·관리자 권한 없음·USB 전달 조건의 전체 시험, 실제 2페이지 형사메모 원본 확인, 실제 인쇄·Edge 저장 위치 선택 정책은 남아 있습니다. 본 결과로 해당 항목을 성공 처리하지 않습니다.

일반 PDF의 임의 다단 구조, 매우 저해상도·손글씨·특수 OCR, 비밀번호 PDF, 이미지가 섞인 페이지의 부분 영역 자동 OCR은 보장하지 않습니다. 혼합 페이지는 필요시 전체 OCR을 선택해야 합니다. 빈 페이지를 OCR해도 텍스트가 없으면 오류와 수동 입력 경로를 제공합니다.

전과·누범·집행유예·반의사불벌·합의·공탁 모듈은 미구현입니다. 사건 자동 보관함도 없습니다. PDF.js main-thread fallback이므로 큰 문서에서 처리 속도가 느릴 수 있습니다.
